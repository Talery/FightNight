# Release audit — 13 августа 2026

## Проверено в репозитории

- `npm run check` включает unit/integration, production build, автоматический release audit и Playwright.
- Отдельная симуляция завершает 1 000/1 000 походов без softlock.
- PWA собирается в 112 precache-записей; route-level code splitting удерживает стартовый JS ниже бюджета 450 KB.
- Отдельный production-PWA тест ждёт активный service worker и заполненный precache, сохраняет героя в IndexedDB, отключает сеть, перезагружает приложение и начинает обычный поход; критический сценарий выдержал 5/5 повторов.
- Сохранения мигрируют до v18; автоматическая матрица проверяет 18 версий хаб-сохранения и 16 версий активного боя, а повреждённая основная запись восстанавливается из backup. Реальные анонимизированные beta-сохранения пока отсутствуют.
- Офлайн-игра, локальный зал павших, экспорт/импорт и очередь сетевой синхронизации покрыты тестами.
- Daily-run использует фиксированный изолированный билд и не может убить или изменить героя кампании; протокол `0.6.0-r1` журналирует allowlist-действия и проходит одинаковый replay в клиенте и Deno Edge runtime.
- В CI добавлен обязательный `npm run check` на push и pull request.
- `npm run check` теперь включает production PWA/offline gate до общей responsive E2E-матрицы.
- Release contract машинно замораживает app `0.2.4`, save v18, RunSummary v2 и daily `0.6.0-r1`; новый каталог production-ассетов без source/license записи останавливает audit.
- Автоматический crash reporting отсутствует и явно запрещён политикой данных до отдельного privacy-решения.
- Installability manifest проверяется через Chromium DevTools Protocol; service worker выполняет update check и остаётся активным перед offline reload.
- Известные ограничения и внешние stop-ship gates опубликованы в `KNOWN_ISSUES.md`, изменения кандидата — в `RELEASE_NOTES_0.2.4_VNEXT.md`.
- Playwright проверяет обучение, бой и сумку на 360/390/768/1280/1920 px, а полный жизненный цикл героя — на одном эталонном проекте; короткий desktop 1280×800 также держит кнопку «В бой» в первом экране.
- Локальный Windows-архив `FightNight-Windows-v0.2.4-vnext-20260813-r6.zip` собран после зелёного `npm run check`; внутри находятся privacy, credits, release notes, known issues и явное описание статуса неподписанного portable-выпуска.
- Автоматический smoke-test реально запустил скрытый Windows launcher, получил HTTP 200 и страницу с `#root`, затем остановил тестовый процесс.

## До реального выпуска требуется внешнее действие

| Требование roadmap | Нужное доказательство | Почему его нет в репозитории |
| --- | --- | --- |
| Production Supabase и сезонный рейтинг | Развёрнутый проект, URL, политика доступа и проверочный запрос | Нет выделенного проекта, учётных данных и права на его создание. |
| Проверяемый daily-рейтинг | Серверный replay журнала действий на production endpoint | Edge Function, схема, RLS, rate limit и локальный Deno check готовы, но production endpoint не развёрнут. |
| Закрытая beta | Отчёты внешних тестеров и triage ошибок | В репозитории есть протокол и шаблон, но нет внешних участников. |
| Полный выпуск | URL опубликованной версии, домен/хостинг, успешный production smoke-test | Нужен выбранный хостинг и доступ к аккаунту публикации. |
| Финальный звук/арт для всех биомов и боссов | Принятый набор ассетов и лицензии | Два атмосферных фона и синтезированные UI-звуки готовы; полный арт-пак требует художественного решения/приёмки. |

## Безопасное правило запуска beta

Не включать переменные `VITE_SUPABASE_*`, пока не развёрнуты серверная проверка daily-run и минимальные RLS-политики. Обычная игра и локальная таблица полностью работают без них.
