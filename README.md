# Пепельный Круг

Одиночная offline-first roguelike-игра о бойцах с перманентной смертью и опциональным общим рейтингом.

Полный поэтапный план разработки: [ROADMAP.md](./ROADMAP.md).
Протокол для внешней проверки: [BETA_TEST.md](./BETA_TEST.md).
Текущее доказательство готовности и внешние release-гейты: [RELEASE_AUDIT.md](./RELEASE_AUDIT.md).
Пошаговый выпуск и откат: [RELEASE_CHECKLIST.md](./RELEASE_CHECKLIST.md).
Замороженный машинно-проверяемый контракт кандидата: [RELEASE_CONTRACT.json](./RELEASE_CONTRACT.json).
Изменения кандидата: [RELEASE_NOTES_0.2.4_VNEXT.md](./RELEASE_NOTES_0.2.4_VNEXT.md). Известные ограничения: [KNOWN_ISSUES.md](./KNOWN_ISSUES.md).

## Запуск

```powershell
npm install
npm run dev
```

Production-сборка и проверки:

```powershell
npm test
npm run build
npm run preview
```

Windows-архив для офлайн-запуска создаётся только после зелёной сборки:

```powershell
npm run build
npm run package:windows
```

Текущий локальный RC-артефакт: [FightNight-Windows-v0.2.4-vnext-20260813-r6.zip](./release/FightNight-Windows-v0.2.4-vnext-20260813-r6.zip).

Для одного локального релизного gate используйте `npm run check`: он запускает все тесты, затем production-сборку. То же самое делает GitHub Actions на каждом push и pull request.

## Что реализовано

- случайный персонаж, включая редкие шуточные имена и 500+ частей имён, титулов и названий предметов;
- сила, ловкость, удача, броня, опыт и распределение очков;
- выбор одного из трёх перков каждые три уровня, отдельное дерево из 78 связанных узлов и редкие мутации героя;
- процедурные походы из 6–10 ветвящихся глубин, восьми биомов, сервисных комнат и альтернативной победы через печати; публичные и ежедневные seed-забеги с фиксированным изолированным стартовым билдом;
- выбор между боями, событиями, схронами, привалами, алтарями и элитными врагами;
- временные благословения и проклятия, меняющие правила конкретного похода;
- мутации противников на высокой сложности;
- тактический бой: зона удара, зона блока, быстрый удар, тяжёлый удар и финт; пять оружейных стилей, активные способности, комбо и фазы боссов;
- боевые типы урона (рубящий, дробящий, колющий, мистический) и состояния: кровотечение, яд, горение, оглушение, страх, слабость и слом брони;
- фракции, шесть архетипов противников, 60 черт, 80 мутаций, 12 именных трёхфазных боссов, Немезида, фракционная добыча, события, условия похода, предметы, аффиксы и квесты;
- экипировка, расходники, добыча, продажа, ограниченная сумка, материалы, 120 аффиксов, 40 реликвий, проклятия, комплекты и кузнечные улучшения/перековка;
- таверна с безопасным и рискованным лечением, фракционные задания/репутация, торг и обновляемая лавка;
- автоматическое сохранение каждого действия в IndexedDB и резервную копию;
- версионированные миграции, восстановление повреждённого сохранения, экспорт и импорт JSON;
- детерминированную генерацию: исходный seed и номер каждого действия сохраняются;
- перманентная смерть, расширенный локальный «Зал павших», эпитафии, финальный билд и экспорт карточки павшего;
- PWA-режим и работа без сети после первого открытия;
- крупный текст, высокий контраст, режим сниженной анимации и регулируемые синтезированные звуки интерфейса/боя с сохранением настройки на устройстве;
- встроенная краткая памятка о маршруте, тактическом бою и перманентной смерти;
- девять атмосферных сцен в оптимизированном WebP, 12 силуэтов бойцов/монстров и отдельные SVG-иконки экипировки;
- опциональная синхронизация рейтинга через Supabase с анонимным ID и очередью повторной отправки после восстановления сети;
- проверяемый daily-протокол `0.6.0-r1`: серверный seed, журнал разрешённых действий, deterministic replay, idempotency key и отдельные daily/season таблицы.

## Генерация контента

Словари и шаблоны находятся в `src/game/content.ts`, а типизированный реестр и его runtime-проверка — в `src/game/registry.ts`. Новый контент добавляется расширением реестра: интерфейс и формат сохранений менять не требуется.

Для редакторской проверки доступен детерминированный `previewContent(seed)` из `src/game/content-preview.ts`: он выдаёт подборку героев, противников, предметов и событий без запуска похода.

Комбинаторная генерация, предметы, бой, события, прогрессия и экономика разделены между модулями `src/game/generation.ts`, `items.ts`, `combat.ts`, `events.ts`, `progression.ts` и `economy.ts`. Формулы и коэффициенты собраны в `src/game/balance.ts`, а `engine.ts` только применяет игровые действия.

Предмет собирается из слота, материала, основы, суффикса, редкости, одной или нескольких характеристик и иногда встроенного перка. Противник — из имени, эпитета, архетипа, черты и коэффициентов сложности/глубины.

Карта сначала создаёт набор потенциальных комнат для каждой глубины. Содержимое выбранной комнаты генерируется только при входе, а невыбранные ветви закрываются. Поэтому одинаковая схема карты всё равно приводит к разным боям, событиям, эффектам и наградам.

## Сохранения

Текущий формат — версия 18. Миграции выполняются последовательно `v1 → … → v18`, сохраняя героя и инвентарь; автоматическая матрица отдельно проверяет хаб и активный бой. Основная запись и резервная копия хранятся отдельно; если основная повреждена, игра автоматически поднимает резервную.

В таверне можно скачать сохранение в JSON и импортировать его на другом устройстве. Файл защищён контрольной суммой. Импорт не позволяет воскресить бойца, который уже числится павшим на текущем устройстве.

## Архитектура и тесты

React-интерфейс разделён на оболочку, боковые панели, домашние экраны, поход и оверлеи. Игровой движок не зависит от React и проверяется отдельно.

`npm test` покрывает полный базовый цикл, детерминированное воспроизведение, реестр контента, миграции, резервное восстановление и экспорт/импорт. Одинаковый seed и одинаковая последовательность действий дают полностью одинаковое состояние; отдельный автопрогон завершает 1 000 походов без softlock.

Лицензии и авторство визуальных материалов перечислены в [ASSET_CREDITS.md](./ASSET_CREDITS.md); машинно-проверяемый реестр наборов находится в [ASSET_PROVENANCE.json](./ASSET_PROVENANCE.json).

## Общий рейтинг

1. Создать проект Supabase.
2. Выполнить `supabase/schema.sql` в SQL Editor.
3. Скопировать `.env.example` в `.env`.
4. Заполнить `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.

Без этих переменных игра полностью работает офлайн и показывает результаты текущего устройства. Клиент ставит несинхронизированные результаты в локальную очередь и повторяет отправку при событии `online`.

Для проверенного daily примените [Supabase schema](./supabase/schema.sql) и разверните Edge Function `supabase/functions/verify-daily`. Обычный рейтинг остаётся явно непроверенным; daily и сезонная таблица содержат только результаты, пересчитанные сервером. Состав сетевых данных описан в [PRIVACY.md](./PRIVACY.md).
