# Пепельный Круг

Одиночная offline-first roguelike-игра о бойцах с перманентной смертью и опциональным общим рейтингом.

Полный поэтапный план разработки: [ROADMAP.md](./ROADMAP.md).

## Запуск

```powershell
npm install
npm run dev
```

Production-сборка и проверки:

```powershell
npm test
npm run build
npm run preview
```

## Что реализовано

- случайный персонаж, включая редкие шуточные имена;
- сила, ловкость, удача, броня, опыт и распределение очков;
- выбор одного из трёх перков каждые три уровня;
- процедурные походы из восьми ветвящихся глубин с десятью уровнями сложности;
- выбор между боями, событиями, схронами, привалами, алтарями и элитными врагами;
- временные благословения и проклятия, меняющие правила конкретного похода;
- мутации противников на высокой сложности;
- тактический бой: зона удара, зона блока, быстрый удар, тяжёлый удар и финт;
- случайные противники, черты, события, условия похода, предметы, аффиксы и квесты;
- экипировка, расходники, добыча, продажа и процедурный ассортимент магазина;
- таверна, лечение, задания и явное сохранение без возможности отката;
- автоматическое сохранение каждого действия в IndexedDB и резервную копию;
- версионированные миграции, восстановление повреждённого сохранения, экспорт и импорт JSON;
- детерминированную генерацию: исходный seed и номер каждого действия сохраняются;
- перманентная смерть и локальный «Зал павших»;
- PWA-режим и работа без сети после первого открытия;
- опциональная синхронизация рейтинга через Supabase.

## Генерация контента

Словари и шаблоны находятся в `src/game/content.ts`, а типизированный реестр и его runtime-проверка — в `src/game/registry.ts`. Новый контент добавляется расширением реестра: интерфейс и формат сохранений менять не требуется.

Комбинаторная генерация, предметы, бой, события, прогрессия и экономика разделены между модулями `src/game/generation.ts`, `items.ts`, `combat.ts`, `events.ts`, `progression.ts` и `economy.ts`. Формулы и коэффициенты собраны в `src/game/balance.ts`, а `engine.ts` только применяет игровые действия.

Предмет собирается из слота, материала, основы, суффикса, редкости, одной или нескольких характеристик и иногда встроенного перка. Противник — из имени, эпитета, архетипа, черты и коэффициентов сложности/глубины.

Карта сначала создаёт набор потенциальных комнат для каждой глубины. Содержимое выбранной комнаты генерируется только при входе, а невыбранные ветви закрываются. Поэтому одинаковая схема карты всё равно приводит к разным боям, событиям, эффектам и наградам.

## Сохранения

Текущий формат — версия 3. Миграции выполняются последовательно `v1 → v2 → v3`, сохраняя героя и инвентарь. Основная запись и резервная копия хранятся отдельно; если основная повреждена, игра автоматически поднимает резервную.

В таверне можно скачать сохранение в JSON и импортировать его на другом устройстве. Файл защищён контрольной суммой. Импорт не позволяет воскресить бойца, который уже числится павшим на текущем устройстве.

## Архитектура и тесты

React-интерфейс разделён на оболочку, боковые панели, домашние экраны, поход и оверлеи. Игровой движок не зависит от React и проверяется отдельно.

`npm test` покрывает полный базовый цикл, детерминированное воспроизведение, реестр контента, миграции, резервное восстановление и экспорт/импорт. Одинаковый seed и одинаковая последовательность действий дают полностью одинаковое состояние.

## Общий рейтинг

1. Создать проект Supabase.
2. Выполнить `supabase/schema.sql` в SQL Editor.
3. Скопировать `.env.example` в `.env`.
4. Заполнить `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.

Без этих переменных игра полностью работает офлайн и показывает результаты текущего устройства. На первом этапе рейтинг доверяет клиенту; проверяемые ежедневные забеги следует реализовать отдельным серверным режимом.
